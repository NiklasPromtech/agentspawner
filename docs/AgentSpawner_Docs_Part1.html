1. System Architecture

AgentSpawner is a browser-automation platform where AI agents independently operate on websites. The architecture has four distinct layers that work together:

┌──────────────────────────────────────────────────────────────────────────┐
│                         USER'S BROWSER (React UI)                        │
│  Home ─── Agent Dashboard ─── Flow Editor ─── Review Actions ─── etc.   │
│                    ↕  REST + SSE (port 5173 → 3001)                       │
└──────────────────────────────────────────────────────────────────────────┘
                              ↕
┌──────────────────────────────────────────────────────────────────────────┐
│                    BACKEND SERVER (Fastify · Node.js · port 3001)         │
│                                                                          │
│   Chat Agent ────────────────────────────────── Anthropic API            │
│   Manager Agent  ←─ Haiku loop (cheap) ───────→ (claude-haiku / sonnet) │
│   Action Flow Agent  ←─ builds flows                                     │
│   Scrape Flow Agent  ←─ builds flows                                     │
│   Setup Agent        ←─ onboarding                                       │
│                                                                          │
│   Flow Runner ────── tool execution ────────────────────┐               │
│   Memory Librarian ← auto-enriches every tool result    │               │
│   Scheduler ──────── node-cron ── wake-up trigger        │               │
│   SQLite DB ──────── drizzle ORM                        │               │
└────────────────────────────────────────────────────────────┼────────────┘
                              ↕ WebSocket                    │
┌──────────────────────────────────────────────────────────── ▼ ──────────┐
│                   CHROME EXTENSION (Manifest V3)                         │

What's on this page

The home page does several things automatically:

  • Resume banners — if you were mid-onboarding or mid-flow-generation when you navigated away, a blue or green banner appears offering to resume. This is stored in localStorage via the drafts utility.
  • Running agent badge — polls GET /agents/:id/status every 8 seconds. Shows a pulsing green "N running" badge in the header.
  • Stop button — calls POST /runs/:runId/stop with optimistic UI (hides the badge immediately, restores if the call fails).
  • Agent cards — each shows: name, status badge, description, model, flow count, today's spend, current task (if running), and action buttons.

The 5 Onboarding Phases

1
Chat & Research
Multi-turn conversation with the Setup Agent. It asks about the platform, goals, company context. Internally it calls web_search to research the company URL provided. Saves progress to localStorage so you can leave and resume.
2
Brief Review
Calls POST /agents/:id/setup/generate which runs the Setup Agent to produce: system prompt, profileBlob (JSON with job description, tone, competitors, allowed/restricted actions), and a list of recommended flows.
3
Flow Planning
Shows the AI-proposed list of flows (scrape + action). User can review names, types, and descriptions. Can add/remove planned flows.
4
Flow Building
Each planned flow is built one at a time using the FlowGenerator AI chat. The generator outputs a full flow definition that gets saved to the DB. Draft state is persisted so you can come back tomorrow.
5
Complete
Agent is created in DB with POST /agents. User is redirected to /agents/:id/setup to review the system prompt and configure API keys.
